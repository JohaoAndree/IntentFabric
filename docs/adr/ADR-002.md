## PARTE A — DECISIÓN (congelada al aceptar)

### 1. Contexto
IntentFabric se desarrolla en Windows 11 con Python 3.14.2, Git y GitHub. El perfil del autor (§3 del Maestro) no confirma Docker ni CI/CD, y Netmiko, Paramiko y Jinja2 constituyen aprendizaje acotado, aceptado con justificación (§6.B). El código SSH no se ejecuta hasta la Etapa 3 (26 oct – 1 nov) y el TI2 se entrega el 2–8 nov. Los algoritmos SSH que ofrecen los equipos del laboratorio (IOS-XE y VRP) se desconocen: la visita al laboratorio está pendiente.

Evidencia consultada:
- Netmiko 4.7.0 y 4.8.0 declaran Python `>=3.10,<4.0` e incluyen 3.14 entre sus clasificadores; ninguna lista 3.15. Esto no demuestra que funcionen en Windows 11 con Python 3.14.2.
- Netmiko 4.8.0 (2026-09-21) es la última versión. Un `netmiko>=4.7` instala la 4.8.0, no la 4.7.0. Su README ofrece los extras `par4` ("compatibilidad con Paramiko 4") y `bulk-encrypt`. No se verificó qué versiones fija `par4` ni qué versión de Paramiko se instala por defecto.
- Paramiko 5.0.0 (2026-05-09) retiró las firmas RSA con SHA-1, los intercambios de claves con SHA-1 y GSSAPI, y elevó a 2048 el módulo mínimo de `diffie-hellman-group-exchange-sha256`. Paramiko 4.0.0 (2025-08-03) retiró DSA; para hosts con DSA, el changelog recomienda mantenerse en la serie 3.x.
- Python 3.15.0 es la última versión estable según python.org/downloads (consulta del autor, 2026-10-12). El calendario oficial (PEP 790) la fijaba para 2026-10-01 y una tercera release candidate la trasladó a 2026-10-09. El soporte de PyYAML, Jinja2, Netmiko y Paramiko para 3.15 no se verificó.

### 2. Alternativas
1. **Verificar primero, restringir después.** Python 3.14.2, Netmiko como extra opcional sin tope adicional de Paramiko, prueba de humo, registro de versiones instaladas y un criterio explícito para restringir.
   - Ventajas: no impone una restricción sin evidencia, la reversión cuesta una línea y aprovecha el entorno ya instalado.
   - Desventajas: un problema de SSH podría aparecer tarde (E3 o laboratorio).
2. **Restringir por precaución.** Python 3.14.2 y, desde el inicio, `netmiko[par4]` o `paramiko<5`.
   - Ventajas: evita en principio los mecanismos retirados en Paramiko 5, y `par4` es una vía documentada por los autores de Netmiko.
   - Desventajas: fija sin demostrar que sea necesario. Se desconoce qué fija exactamente `par4`. Un tope `<5` tampoco resuelve el caso DSA.
3. **Intérprete conservador.** Python 3.13 desde el inicio, sin tope de Paramiko.
   - Ventajas: menor incertidumbre de compatibilidad con las librerías.
   - Desventajas: obliga a recrear el entorno, y el posible problema de Paramiko no se resuelve.
4. **Última versión estable.** Python 3.15.0, sin tope de Paramiko.
   - Ventajas: versión vigente con el mayor plazo de soporte.
   - Desventajas: Netmiko no declara soporte para 3.15, la versión tiene pocos días de publicada y el soporte de las demás dependencias no está verificado. Obliga a recrear el entorno.

### 3. Criterios de elección
- **Evidencia suficiente:** una dependencia solo se restringe si la verificación lo demuestra.
- **Soporte declarado de las dependencias:** el intérprete debe estar respaldado por los metadatos de las librerías críticas (Netmiko).
- **Costo de reversión:** cambiar de intérprete o fijar una librería debe costar poco.
- **Hitos:** SSH no debe bloquear E1, E2 ni la exposición del 16 oct.
- **Reproducibilidad del experimento:** las versiones exactas deben quedar registradas.
- **Tiempo disponible:** la configuración del entorno no debe consumir la semana de la exposición.

### 4. Decisión
Se adopta la alternativa 1: Python 3.14.2 como entorno principal, `requires-python = ">=3.13"`, Netmiko como extra opcional (`netmiko>=4.8,<5`) sin tope adicional de Paramiko, registro de versiones instaladas y criterio explícito para restringir Paramiko o cambiar de intérprete. Se acepta cerrar la Etapa 0 con SSH "pendiente" si la instalación falla; en ese caso, el lock cubre solo el entorno verificado. Python 3.15 no se adopta en E0 y se reevalúa tras el TI2.

### 5. Sustento
Con SSH fuera de E1 y E2, restringir ahora constituiría una medida sin pruebas, y fijar después cuesta una línea y regenerar el lock: la alternativa 1 cumple los criterios de evidencia y reversión. La alternativa 2 decide con información incompleta, porque se desconoce el contenido de `par4`. La alternativa 3 consume tiempo del sprint sin resolver el riesgo de Paramiko. La alternativa 4 incumple el criterio de soporte declarado: ningún clasificador de Netmiko cubre 3.15. El registro de versiones instaladas atiende la reproducibilidad en todos los casos, pero solo la alternativa 1 evita decidir antes de tener evidencia.

### 6. Consecuencias y riesgos aceptados
- La negociación SSH puede fallar con un equipo antiguo. Se detectaría al probar en el laboratorio o en un entorno virtual.
- La combinación Netmiko, Python 3.14 y Windows no ha sido probada. Se mitiga con las verificaciones de la sección 8 y con 3.13 como respaldo.
- `>=3.13` es el mínimo elegido. Las versiones realmente verificadas se registran en la sección 10; no se promete compatibilidad con otras, incluida 3.15.
- `requirements.lock` es la captura de un entorno Windows con una versión de Python concreta, no una garantía multiplataforma.

## PARTE B — ESPECIFICACIÓN DE IMPLEMENTACIÓN (para el agente)

### 7. Alcance y fuera de alcance
- Incluye: `pyproject.toml`, `src/intentfabric/__init__.py`, `.gitignore`, `README.md`, `scripts/check_env.py`, `tests/unit/test_smoke.py`, `tests/unit/test_check_env.py`, `requirements.lock` y el llenado del registro de la sección 10.
- NO incluye: subpaquetes (ADR-001), lógica de negocio, conexión SSH real, `paramiko<5` o `netmiko[par4]` ya aplicados, credenciales (ADR-010), CI, Docker, instalar intérpretes de Python, ni el walkthrough (lo redacta Johao).

### 8. Pasos de implementación
Cada paso constituye un punto de control (ver AGENTS.md, sección Git).
1. **Paquete y metadatos.** `pyproject.toml` con setuptools y layout `src/`:
   - Nombre de distribución `intentfabric`, versión `0.1.0`, `requires-python = ">=3.13"`.
   - Dependencias: `PyYAML>=6.0`, `Jinja2>=3.1`.
   - Extra `ssh = ["netmiko>=4.8,<5"]` y extra `dev = ["pytest>=8"]`.
   - Descubrimiento de paquetes en `src/` y `testpaths = ["tests"]` para pytest.
   - Crear `src/intentfabric/__init__.py` solo con un docstring de una línea, sin `__version__`. No crear otros módulos.
2. **`.gitignore`:** `.venv/`, `.venv313/`, `.venv-verify/`, `__pycache__/`, `*.egg-info/`, `.pytest_cache/`, `build/`, `dist/`, `.env`, `logs/`, `runs/`. No ignorar `requirements.lock`.
3. **`scripts/check_env.py`.** Expone `main(lookup=importlib.metadata.version, python_version=platform.python_version) -> int` y se ejecuta con `raise SystemExit(main())`.
   - Imprime estas líneas, en este orden: `python`, `PyYAML`, `Jinja2`, `netmiko`, `paramiko`, con el formato `<nombre>: <versión>`.
   - Si falta una librería, imprime `<nombre>: no instalado` (captura `importlib.metadata.PackageNotFoundError`).
   - La versión de Python sale de `platform.python_version()` y las demás de `importlib.metadata.version()`.
   - El major de Paramiko se obtiene con `int(version.split(".")[0])`, sin dependencias nuevas. Si es 5 o superior, agrega la línea: `ADVERTENCIA: Paramiko >=5 retiró SHA-1 (firmas RSA e intercambio de claves); verificar compatibilidad SSH con los equipos del laboratorio.` Si la versión no se puede interpretar, no agrega advertencia.
   - Devuelve siempre `0`, incluso con librerías opcionales ausentes.
4. **Pruebas.**
   - `tests/unit/test_smoke.py`: importa `yaml`, `jinja2` e `intentfabric`. Un test aparte usa `pytest.importorskip("netmiko")` y verifica que se importa.
   - `tests/unit/test_check_env.py`: carga el script con `importlib.util.spec_from_file_location` (`scripts/` no es un paquete) y prueba `main` con un `lookup` simulado. Casos: todo instalado (5 líneas, código 0); `netmiko` ausente (línea "no instalado", código 0); Paramiko `5.0.0` (aparece la advertencia); Paramiko `4.0.0` (no aparece); la línea de Python va primera.
5. **`README.md`:** requisitos, instalación inicial (usa los rangos de `pyproject.toml`), instalación reproducible (`python -m pip install -c requirements.lock -e ".[dev]"` y la variante con `".[dev,ssh]"`), actualización deliberada del lock (solo con autorización de Johao y con registro), verificación (`python scripts/check_env.py` y `python -m pytest -q`). Aclarar que el lock es la captura de un entorno concreto y que importar Netmiko no prueba una conexión real.
6. **Verificación base.** En un entorno limpio `.venv`: instalar `".[dev]"`, ejecutar `check_env.py` y `python -m pytest -q`. Registrar el resultado en la sección 10.
7. **Verificación SSH.** Instalar también `".[ssh]"` en el mismo entorno, ejecutar `check_env.py` y `python -m pytest -q`. Clasificar el resultado como "SSH: instalación e importación verificadas (conexión real no comprobada)" o "SSH: pendiente (fallo documentado)". Si falla, conservar el mensaje de error y aplicar el paso 9.
8. **Lock y reproducibilidad.**
   - Generar `requirements.lock` con `python -m pip freeze --exclude-editable` desde el entorno donde pasó la verificación: con SSH verificado, desde el entorno con `[dev,ssh]` (alcance "dev+ssh"); con SSH pendiente, desde el entorno con `[dev]` (alcance "dev, SSH pendiente").
   - Verificar en un entorno temporal `.venv-verify`: instalar con `-c requirements.lock -e ".[dev]"` (o `".[dev,ssh]"` según el alcance), ejecutar `check_env.py` y `python -m pytest -q`, confirmar que las versiones de las cuatro librerías coinciden con el lock y eliminar el entorno.
   - Registrar el alcance del lock en la sección 10.
9. **Contingencias (el agente informa y se detiene; decide Johao).**
   - **Python 3.13:** solo si el fallo se atribuye a incompatibilidad con Python 3.14 o a falta de dependencias para ese intérprete. Corregir antes los errores del proyecto o de su configuración. Conservar el error y documentar el diagnóstico. Si Johao lo autoriza e instala el intérprete: crear `.venv313`, reinstalar, repetir los pasos 6 a 8 y registrar cuál queda como entorno de referencia y de cuál se genera el lock.
   - **Python 3.15:** no se utiliza en este ADR. Cualquier prueba con ese intérprete requiere autorización de Johao y queda como verificación aparte en la sección 10.
   - **Paramiko:** proponer `paramiko<5` o `netmiko[par4]` únicamente cuando el diagnóstico identifique una incompatibilidad causada por mecanismos retirados en Paramiko 5 (firmas RSA con SHA-1, intercambios con SHA-1, módulo menor a 2048, GSSAPI). Antes de proponer `par4`, confirmar qué versiones fija. Registrar error, mecanismo y versiones. Johao autoriza el cambio; después se repiten instalación, pruebas, verificación SSH y lock. Un caso DSA no se resuelve con `<5` (se retiró en Paramiko 4): solo reportar. Es una solución candidata, no una garantía de conexión.

### 9. Criterios de aceptación
- `python -m pip install -e ".[dev]"` termina sin errores en un entorno limpio. `python scripts/check_env.py` devuelve código 0 e imprime las versiones. `python -m pytest -q` queda en verde, con a lo sumo el test de Netmiko omitido.
- SSH: instalación e importación verificadas, o fallo documentado con diagnóstico. En este último caso el ADR puede cerrarse con SSH "pendiente".
- Un test SSH omitido significa "no comprobado". Nada de este ADR prueba una conexión real.
- `requirements.lock` está versionado en Git, no contiene líneas `-e`, y su alcance está registrado. Instalar con `-c` en un entorno limpio reproduce las versiones de las cuatro librerías.
- Git ignora entornos virtuales, cachés y metadatos de instalación. El README, el script, las pruebas y el lock están versionados, y el árbol queda limpio.
- La sección 10 está completa.
